# Clean contour check

The cards below apply to **one place in the code**: a fragment of 30-60 lines
around the line that was found. You do not need to know the whole project:
everything required for an answer is in the fragment, or the answer is
"unclear".

## Procedure

1. Take a card. Run its **search** over the files being checked (your own diff,
   the file being fixed, or an area the owner named). Every hit is a
   candidate.
2. Discard candidates that fall under **does not count**.
3. Open the fragment around the candidate and answer the card's **questions**
   in order: `yes`, `no` or `unclear`. An answer rests on a line of the
   fragment; a guess about code outside it is `unclear`.
4. The verdict follows the card's **dirty if** line. `unclear` on a question
   the verdict depends on makes the verdict `unclear`, and the place goes to a
   human or a strong model.
5. Write the output line.

Output is one line per candidate:

```
file:line | C<number> | answers, comma separated | dirty / clean / unclear | one sentence: what comes from where
```

A dirty place in your own diff is fixed before the task is closed. A dirty
place outside the diff is a line in the report, not a fix "while at it".

Signs that a machine looks for without reading, such as a new state field
without a declaration or a set of values outside the declaring module, sit in
the project's CI; here they appear only where a question to the code is needed.

**Languages.** The questions apply to any language; the code examples are in
Python and TypeScript. Each search names the Python and TypeScript signs first,
then the signs for Kotlin (and Java), Go and C#. Where a project has no ORM,
state is written and read in SQL strings, so search those too. Tests in those
languages are `src/test/`, `*Test.kt`, `*_test.go`, and in C# the `*.Tests`
projects, `*Tests.cs`, classes with `[Fact]`, `[Theory]`, `[Test]`. EF Core
migrations (`Migrations/*.cs`, `*.Designer.cs`) and generated code
(`*.g.cs`, `obj/`, any file with a `<auto-generated>` header, such as Razor
pages compiled into `*.cshtml.cs`) are excluded from every search; a hit there
is read in its source (`.cshtml`, `.razor`).

---

**Which cards go to whom.** A weak model (cheap, without reasoning) gets the
cards that passed the exam from the `exam/` directory with threshold 90/10; on
11.11.2026 (DeepSeek flash) C1, C4, C7, C8, C14 and C15 were not passed, and C10
passed but was mostly wrong on real code, so their candidates are checked by a
strong model or a human. A weak model's `dirty` is a candidate: a strong model
reads it before it is reported.

## C1. State derived from an event log

**Search:** functions that walk over events and return a state, stage, result,
or "is it finished": `*_from_events`, `compute_*state*`, `fold`, `reduce` over
a list of events; a loop over `events` with `return` of a status;
`any(e.type == …)`, `.some(e => e.type === …)`.

**Kotlin and Go:** in SQL, `DISTINCT ON (…)` or `ORDER BY … DESC LIMIT 1` over a
table named `*_events`, `*_results`, `*_runs`, `*_log`, whose value is scanned
into a status type or returned as one; helpers like `latestOfType(`,
`json_extract(data,`. Version and settings tables (`*_versions`, `settings`) read
the same way are not a state. `range events`, `events.any {` and `valueOf(` are
mostly noise.

**C#:** LINQ over an event collection that returns or assigns a status:
`events.Any(e => e.Type == …)`, `.OrderByDescending(e => e.CreatedAt).FirstOrDefault()`
over a `DbSet<*Event>`, `*Results`, `*Runs`, `*Log` whose `.Type`/`.Status` is
returned as the entity's state, `.Aggregate(` over events, `.LastOrDefault(e =>`.
In Dapper or raw SQL: `ORDER BY … DESC` with `TOP 1` / `LIMIT 1`,
`ROW_NUMBER() OVER (PARTITION BY` over an events table, `JSON_VALUE(data,`.
Event sourcing (Marten, EventStoreDB): an inline projection that persists the
state document is the stored field; `AggregateStreamAsync` or a live
`Apply(`/`When(` fold in a read path that decides a status is a candidate.

**Questions:**
1. Does the fragment return or set a state, stage, result, or a
   "finished / interrupted / checked" flag of an **entity**? The answer to a
   query ("did this key already arrive?") is not an entity state.
2. Is the value taken from a list of events (a log), not from a field of the
   entity?
3. Does the entity have a stored field with the same meaning (`status`,
   `state`, `result_status`, `stage` and the like), in the fragment or in its
   imports?

**Dirty if:** 1 = yes and 2 = yes. Question 3 = yes makes the place worse: the
stored field exists, yet the log is what gets read.

**Does not count:** a data migration module (a migration, `*_backfill`) that
folds the log into a stored field once; a report that counts the time or
frequency of events, not a state; a repeated-request check by an idempotency
key; tests.

**Dirty:**
```python
def attempt_finished(events):
    return any(e.type == "attempt_completed" for e in events)
```
**Clean:**
```python
def attempt_finished(attempt):
    return attempt.status in AttemptStatus.FINAL
```

## C2. A missing row is read as a state

**Search:** a branch on an empty selection or on `None` from a query:
`if not rows`, `if row is None`, `.first() is None`, `count() == 0`,
`exists(`, `len(…) == 0`, followed by a return or an assignment of a state. The
fragment also includes the declaration of the entity with its state fields.

**Kotlin and Go:** a branch on an empty result that **returns or assigns a status**:
`firstOrNull() ?: <Enum>.`, `?: return "<STATE>"`, `when (x) { null -> <STATE>`,
`?.status?.isX != true`, `errors.Is(err, sql.ErrNoRows)` followed by `return
"<state>"`, `SELECT EXISTS` in a function returning a status, SQL
`coalesce(…, '<STATE>')`. The same branch followed by `throw NotFound` or
`return ErrNotFound` is a 404 and does not count.
Keep only hits where a status is returned or assigned within three lines;
`?: return` in a route handler that answers 400 or 401 does not count. A
`COUNT(*) … > 0` returned as a bool from a function named `*Locked`, `Has*`,
`Can*` counts.

**C#:** a branch on an empty result that **returns or assigns a status**:
`FirstOrDefaultAsync(…) is null` / `== null` followed by `return <Enum>.`,
`?? <Enum>.NotStarted`, `!await db.X.AnyAsync(`, `CountAsync() == 0`,
`switch { null => <Enum>.X }`, Dapper `QuerySingleOrDefaultAsync` checked for
null, SQL `COALESCE(…, '<STATE>')`, `CASE WHEN EXISTS`. The same branch followed
by `return NotFound()`, `Results.NotFound()`, `throw new *NotFoundException`,
`Unauthorized()`, `BadRequest()` does not count. An `AnyAsync(` returned as a
bool from a method named `Is*`, `Has*`, `Can*` counts.

**Questions:**
1. Does a branch on an empty selection (no rows, `None`, a zero count, "does
   not exist", an empty id) return or assign a state value: a status name or
   literal, an enum member, a `state=`/`status=` field ("not started", "not
   ready", "no access", "no account", "empty"), a result object whose flag or
   reason says ready / not ready, or a bool from a function named
   `is*`/`has*`/`can*`? An empty list, a 404, an exception, passing `None` on,
   or a default for a calculation is "no".
2. Are the rows that turned out empty other rows than the state field of the
   entity the value is about (grants of an employee, answers of a step, photos
   of a shipment, rows of an upload)? An empty foreign key (`user_id is None`)
   stands for a missing row of another table and is "yes". Reading that
   entity's own state field is "no". Whether the entity also has a stored field is not asked: answer from
   the branch itself.

**Dirty if:** 1 = yes and 2 = yes.

**Does not count:** a 404 for a request for a nonexistent object; an "already
created?" check before creating that same row; tests.

**Dirty:**
```python
if session.query(Answer).filter_by(step_id=step.id).first() is None:
    step_state = "not_started"
```
**Clean:**
```python
step_state = step.state
```

## C3. State taken from a neighboring entity

**Search:** reading `status`/`state` of another table or object, after which
the state of its own entity is set; comparing the status of a job, queue, or
run inside a function that returns the status of a draft, blueprint, or
assignment.

**Kotlin and Go:** no single sign; look in files named `*Queries`, `*Facts`,
`*View*`, access and entitlement code, and SQL that joins the status of another
table into a status of its own (`EXISTS (SELECT 1 FROM … WHERE status`).

**C#:** EF Core `.Include(x => x.Job)` followed by `x.Job.Status ==` in a
method or property that returns the status of `x`; a projection
`Select(d => new … { Status = d.Run.Status == … ? … })`; an expression-bodied
property `Status => Job.State switch {`; SQL `EXISTS (SELECT 1 FROM … WHERE
status`. Look in `*Query`, `*ReadModel`, `*Projection`, `*ViewModel`, `*Dto`
mappers (AutoMapper `ForMember(d => d.Status, …)`), and authorization code
(`AuthorizationHandler<`, policy requirements).

**Questions:**
1. Does the fragment return or write the state of entity A?
2. Is the state of A **derived** from a field of entity B (another table,
   another object, another service's response)? If the status of B is only
   returned next to the status of A as a separate field, the answer is "no".
3. Does A have its own state field that takes no part in the decision or takes
   part second?

**Dirty if:** 1 = yes and 2 = yes.

**Does not count:** a writer of A that, on an event of B, **moves** A to a new
stored state in one transaction; tests.

**Dirty:**
```python
def blueprint_status(bp, job):
    return "failed" if job.status == "failed" else "generating"
```
**Clean:**
```python
def blueprint_status(bp):
    return bp.status  # the writer moves it on the job's outcome
```

## C4. A state field written around the writer

**Search:** assignments `.status =`, `.state =`, `.stage =`, `.phase =`,
`.outcome =`, `.processing_status =`, `update(...).values(status=…)`.

**Kotlin and Go without an ORM:** the writes are in SQL strings. Search
`SET\s+\w*status\w*\s*=` (it also catches `status='X'`, `lifecycle_status`,
`payment_status`, and a `SET` on the line above), then look whether the same
statement guards the old value (`WHERE … status =`, `status IN`, `= ANY(`). A
`.status =` or `.Status =` search alone mostly hits `WHERE` predicates, `const`
blocks and test fixtures. With an ORM or a struct: `.copy(` with `status =` on
the next lines, Exposed `it[…Table.status] =`, Go `inv.Status = …` followed by
`repo.Update(`, ent `.SetStatus(`. Writers are named `setStatus`, `applyEvent`,
`Transition`, `MarkFailed`.
Put `copy(status =` / `copy(state =` first for immutable Kotlin models. The
status can sit mid-list in a `SET` (`, payment_status = $3`), and a state can be
a boolean flipped in place (`SET is_active = NOT is_active`, `is_locked`,
`is_approved`). In Go the useful pair is a `.Status =` in the caller followed by
a repository `Update(ctx, x)` that writes the whole struct with no status in its
`WHERE`.

**C#:** `.Status =`, `.State =`, `.Stage =` outside the entity; a record
`with { Status = … }` followed by `Update(`/`SaveChangesAsync`; EF Core
`ExecuteUpdateAsync(s => s.SetProperty(x => x.Status, …))`;
`Entry(x).Property(p => p.Status).CurrentValue =`; Dapper or raw SQL
`SET\s+\w*status\w*\s*=` with no guard of the old value in the `WHERE`. A
property declared `{ get; set; }` on an entity with a lifecycle is itself a
reason to search its writers; with `{ get; private set; }` the compiler already
confines writes to the entity, so look only inside it for methods that assign
it besides the writer. Writers are named `TransitionTo`, `ChangeStatus`,
`Apply`, `MarkFailed`. An object initializer `new Order { Status =
OrderStatus.Draft }` in the entity's own factory is creation.

**Questions:**
1. Is this an assignment to the state field of an entity with a lifecycle?
2. Is the fragment not the write function of this field itself (its name is
   usually `set_*_status`, `transition_*`, `*_writer`)?
3. Does the fragment contain no call to a write function that checks the
   transition?

**Dirty if:** 1, 2 and 3 = yes.

**Does not count:** the write function; a migration; a factory in tests;
creating an entity with an initial state from the list inside its own module.

**Dirty:**
```python
version.processing_status = "ready"
```
**Clean:**
```python
set_version_processing_status(version, ProcessingStatus.READY)
```

## C5. One state computed in several places

**Search:** the machine collects functions with similar names (`*_status`,
`*_state`, `is_*_ready`, `*_verdict`, `*_outcome`) for one aggregate and gives
the model pairs.

**Kotlin and Go:** the same names (`isReady`, `CanOpen`), but most duplicates are SQL
predicates with no function name: compare `status NOT IN (…)`, `status <> '…'`,
`CASE status WHEN …` and `payment_status != '…'` across files.

**C#:** the same names as properties or methods (`IsReady`,
`CanOpen`, `IsOverdue =>`), and LINQ predicates with no name:
`.Where(o => o.Status != … && …)` repeated across queries and services,
`Expression<Func<T, bool>>` fields, SQL `CASE status WHEN` in Dapper strings. A
shared specification or extension method (`o.IsOpen()`, `Specs.Open`) that both
places call is the "one shared function".

**Questions (about a pair of fragments):**
1. Do both fragments compute the same outcome for the same entity? The same
   outcome: the same name or a synonym (finished / ready / done / publishable;
   passed / accepted; empty / nothing found), or the same set of output values
   (both map one status to a label, a stage or a badge). Different outcomes:
   opposite or neighbouring actions (open / close, cancel / refund), different
   times (was ever applied / is in force now), different entities (order /
   shipment). Judge by the names and the returned values, not by how the
   conditions are written: a condition that differs is question 3, not a
   reason for "no". If the answer is "no", questions 2-3 are not asked.
2. Is the answer computed, rather than read from one stored field or one shared
   function?
3. Do the calculation rules in the fragments differ by at least one branch?

**Dirty if:** 1 = yes and 2 = yes. Question 3 = yes means the divergence is
already visible to the user.

**Does not count:** one function and its thin wrapper that only calls it.

**Dirty:**
```python
# a.py
def passed(att): return att.score >= 80
# b.py
def passed(att): return att.score > 80 and not att.disputed
```
**Clean:**
```python
# both places
from attempts import attempt_passed
```

## C6. A decision by error text or code prefix

**Search:** `in str(exc)`, `in message`, `.lower()` on error text,
`.startswith(` / `.removeprefix(` on a refusal code; in the frontend
`.includes(` on `detail`, `message`, `error`.

**Kotlin:** `message.contains(`, `message?.contains(`, `.message` with
`.startsWith(`, a `Regex` applied to the message (`Regex(…).find(it)` inside
`message?.let`), an exception handler that cuts a code out of `e.message`.
**Go:** `strings.Contains(err.Error(),`, `err.Error() ==`, `MatchString(` on
`err.Error()` or a lowered message. `errors.Is`, `errors.As` and a check of a
`pq.Error`/`pgconn.PgError` code are clean. **TS:** `.match(/…/)` and
`/…/.test(` on a message. `.startsWith(` on provider ids (`pi_`, `cs_`, `sk_live_`)
inside the adapter that declares them does not count.

**C#:** `ex.Message.Contains(`, `.Message.StartsWith(`,
`ex.Message ==`, `ex.ToString().Contains(`, `Regex.IsMatch(ex.Message`, an
exception filter `catch (…) when (ex.Message.Contains(…))`,
`problem.Detail.Contains(` on a client, `response.ReasonPhrase ==`, `.Code.StartsWith(` on a
refusal code. Clean: `catch (TimeoutException)`, `catch (TaskCanceledException)
when (!ct.IsCancellationRequested)`, `PostgresException.SqlState ==
PostgresErrorCodes.…`, `SqlException.Number`, `HttpRequestException.StatusCode`,
a typed `ErrorCode` property. `.StartsWith(` on provider ids inside the adapter
that declares them does not count.

**Questions:**
1. Does the branch choose behavior (refusal code, retry, text for the user,
   kind of failure)?
2. Is the choice made by the message text or by the start of a code string,
   rather than by a member of a list or an exception class?

**Dirty if:** 1 = yes and 2 = yes.

**Does not count:** writing to a log; a test that checks the message text.

**Dirty:**
```python
if "timeout" in str(exc).lower():
    code = "provider_timeout"
```
**Clean:**
```python
except ProviderTimeout:
    code = FailureCode.PROVIDER_TIMEOUT
```

## C7. A kind or role guessed from an indirect sign

**Search:** comparisons with a label, a literal in natural language, an id
prefix, a unit of measure, or cell text: `== "…"` against a natural-language UI
label literal, `.startswith("<prefix>:")`, `unit === "steps"`,
`label.includes(`, `columns.index("…")`, `id.includes(" ")`.

**Kotlin and Go:** an id prefix that chooses the processing (`HasPrefix(…ID`,
`startsWith("as-is:`), a body or note text compared to a constant, a kind read
from whether a foreign key is null (`packageId == null`). Path, URL, host and
header parsing is noise.

**C#:** `string.Equals(label, "…", StringComparison.OrdinalIgnoreCase)`
or `== "…"` against a natural-language literal, `Id.StartsWith("…:")`,
`Unit == "pcs"`, `Name.Contains(' ')`, `x.GetType().Name ==`, a kind read
from a nullable foreign key (`x.ParentId == null`, `PackageId is null`) or
from which derived class an object deserialized into, when the class has a
`Kind` property. `Enum.Parse`/`TryParse` of a declared enum inside its parsing
method is the declaration. Path, URL, host and header parsing is noise.

**Questions:**
1. Does the branch decide how the object is processed next (the kind of an
   object, the role of a column, whether a variant is a service one, an order or
   a refund)? The test the fragment itself answers: does a value computed in
   this branch reach anything that is not a string shown to the user — a stored
   field, a next call, a refusal, a filter, a price, a route? If both arms only
   produce strings for the interface, the answer is "no".
2. Is the answer obtained from a label, text, prefix, unit, or the shape of a
   string, rather than from a kind field (`kind`, `type`, `role`, a flag)?
3. Is a stored kind field present nearby, in the fragment or in the response
   schema?

**Dirty if:** 1 = yes and 2 = yes.

**Does not count:** the module where this prefix or label is **declared** (one
`parse_*` function); translating a label for display; a branch that chooses
only display text by unit or label; a comparison with a member of a declared
list (`value === "custom"` with `type Size = "small" | "custom"`); tests.

**Dirty:**
```ts
const isPallet = order.sizeUnit === "pallets";
```
**Clean:**
```ts
const isPallet = order.kind === "pallet";
```

## C8. A negative check of the kind

**Search:** `not is_<kind>`, `!is<Kind>`, `!= Kind.`, `!== "…"` in a condition
that chooses the processing.

**Kotlin and Go:** `!is `, `.Kind != `, `!= Kind.`. `!in setOf(…)` followed by a
refusal does not count. In Go, kind dispatch is often a `switch` whose
`default:` does real work for "everything else". If the "kind" is a lifecycle role, the card does not
apply: that is C4.

**C#:** `is not <Type>`, `!(x is <Type>)`, `.Kind != Kind.`,
`!= OrderType.`, `!IsPallet(`. A `switch` statement whose `default:` or a
switch expression whose `_ =>` arm does real work for "everything else" is a
negative check written as a positive one. `is not <Type>` followed by `throw`
or `return Error(` does not count; `is not null` is not a kind.

**Questions:**
1. Does the branch choose the **processing** (what to do with the object next)
   by the kind of the object? A branch whose only action is a refusal (`raise`,
   returning an error) does not choose processing.
2. Is the condition "not such-and-such kind", rather than "such-and-such kind"
   or an entry from a table of kinds? A kind is the value of the object's kind
   field (`kind`, `type`, role). Validity, emptiness, whether a day is a
   holiday, a flag are not a kind: "no".

**Dirty if:** 1 = yes and 2 = yes.

**Does not count:** a branch whose only action is a refusal (`raise`, returning
an error with a code): "this kind is not accepted here"; a check of a sign that
is not a kind (whether an index is valid, whether it is a holiday).

**Dirty:**
```python
if not is_pallet(order):
    build_parcel_route(order)
```
**Clean:**
```python
PLANS[order.kind].build(order)
```

## C9. A set of values declared more than once

**Search:** the machine finds literal sets of three or more strings (`set`,
`frozenset`, `tuple`, `Literal[...]`, an array, a union type) and gives the
model pairs with the same or almost the same contents, and also a set next to
an API list (an `enum` in an OpenAPI schema, a generated type).

**Kotlin and Go:** the main duplicates are SQL `IN ('A','B','C')` in strings;
compare them with each other and with the enum or `const` block. Also
`setOf(`/`listOf(` and `[]string{` over several lines, Exposed
`inList(listOf(`, `@SerialName` values that copy a domain enum, a migration
`CHECK (status IN …)`. **TS without generated types:** `new Set([`, arrays of
three or more strings next to `.includes(x.status)`, hand-written unions in
`types.ts`.
Also `case "a", "b", "c":` in Go, `when (x) { "A" -> …` string branches repeated
across Kotlin modules, `html/template` ladders `{{if eq .X "a"}}…{{else if eq .X
"b"}}`, and SQL `CASE … WHEN` / `ORDER BY CASE` over the same statuses.

**C#:** an `enum` next to `new[] { "a", "b", "c" }`, `new HashSet<string> {`,
`ImmutableHashSet.Create(`, a collection expression `["a", "b", "c"]`, a
`static class` of `const string` that mirrors an enum, `[EnumMember(Value =
"…")]` or `[JsonStringEnumMemberName("…")]` values that copy a domain enum,
`case "a": case "b":` or `"a" or "b" or "c"` patterns repeated across files,
SQL `IN ('A','B','C')` in Dapper strings, and an EF Core
`HasCheckConstraint("…", "status IN (…)")` written as a literal instead of
built from `Enum.GetNames`. A type generated from the API contract (NSwag,
Kiota, OpenAPI Generator) is not a copy.

**Questions (about a pair):**
1. Do both sets list the same thing: state values, kinds, refusal codes, ids of
   the options of one question? Calendar and physical constants (days of the
   week, months, sizes) are "no".
2. Is at least one of them written as a literal rather than obtained from the
   other (import, generation, `Enum.__members__`, a generated type)?
3. Do the contents differ by at least one value?

**Dirty if:** 1 = yes and 2 = yes, whatever the answer to question 3: contents
that match today will diverge at the next edit of one of the places. Question
3 = yes means the divergence already exists.

**Does not count:** a subset declared by **name** next to the list whose
members the compiler checks against that one list: enum members (`FINAL =
{A.DONE, A.FAILED}`) or literals typed by the imported or generated union
(`new Set<ShipmentStatus>(["delivered", "returned"])`); fixtures and test parametrization; sizes,
colors and other presentation values (`"xs" | "sm" | "md"`).

**Dirty:**
```ts
type Status = "pending" | "approved" | "rejected";  // a copy of the API enum
```
**Clean:**
```ts
type Status = components["schemas"]["ExtensionStatus"];
```

## C10. All or nothing

**Search:** processing a list of parts (sections, steps, blocks, files) where
the failure of one part sets a failure of the whole: `raise` inside a loop over
parts, `status = "failed"` after the first error of a part, `Promise.all`
without examining the results.

**Kotlin:** `throw` or `return Outcome.Err` / `return@…` inside `for`, `.map {`,
`.forEach {` over parts under one `@Transactional`.
**Go:** `return err` inside `for … range parts`; `errgroup` over parts of one
result, where the first error cancels the rest.

**C#:** `throw` or `return Result.Fail(`/`return Error(` inside `foreach`
over parts before one `SaveChangesAsync`, inside one
`BeginTransactionAsync`/`TransactionScope`; `await Task.WhenAll(parts.Select(…))`
where the first exception discards the other results; `Parallel.ForEachAsync`
over parts of one result; a `CancellationTokenSource.Cancel()` in a part's
`catch`.

**Questions:**
1. Name the one object or field that receives an overall status or result
   built from these parts (a report from sections, an application from files,
   a task from labels). A notification, a toast, a log line, a response to a
   bulk request, or a list of independent records (orders, rows, routes) is not
   such an object. If it cannot be named from the fragment, the answer is "no".
2. Does the failure of one part set the overall status (`failed`), discard the
   results of the other parts, or stop the processing of the rest?
3. Is it declared in the fragment that the parts are required together: a
   type or a constant that lists the required composition? A comment, a
   function name, or a guess about intent is not a declaration. Nothing
   declared is "no".

**Dirty if:** 1 = yes, 2 = yes and 3 = no.

**Does not count:** parts that by type are all required together, and this is
declared in the plan or the type; `Promise.all` and a loop over independent
records (orders, table rows) that have no shared status.

**Dirty:**
```python
for section in sections:
    generate(section)   # the first exception fails the whole build
```
**Clean:**
```python
results = [generate_part(s) for s in sections]   # each part has its own outcome
```

## C11. A wait without a failure state

**Search:** a call to a model, network, queue, or background handler; writing
`pending`, `processing`, `generating`, `queued` before long work; `await` /
polling without a limit.

Better than searching the call: find the **waiting literal** and check that
something moves it out. Search writes of `'PENDING'`, `'PROCESSING'`,
`'RUNNING'`, `'SYNCING'`, `ACTIVE` with a holder, including an `INSERT` into a
table whose column has `DEFAULT 'PENDING'`; then look for a sweeper or worker
whose `WHERE status =` reads the same literal and has a path to a final state.
A retry that only does `attempts + 1` with no limit, and a status whose only
outgoing transition is success, are dirty. Workers: Kotlin `@Scheduled`,
`scope.launch { while (true) { delay(`; Go `time.Ticker`, `for {` with a
logging error branch.
Status literals may be lowercase (`'processing'`) or constants
(`RefundStatusPending`); search the constants too. An app with no model calls,
queues or background workers, where "pending" means a human decision, has
nothing for this card.

**C#:** writes of `Status.Pending`, `Processing`, `Queued`, `Running`
followed by `SaveChangesAsync` and then `await _http.`, `_bus.Publish(`,
`_queue.EnqueueAsync(`, `BackgroundJob.Enqueue(`; an `INSERT` into a table whose
column has `HasDefaultValue(…Pending)`. Then look for the worker whose query
reads the same literal and has a path to a final state: `BackgroundService` with
`while (!stoppingToken.IsCancellationRequested)`, `PeriodicTimer`, Hangfire
recurring jobs, Quartz `IJob`, a lease column (`LeaseUntil < now`). Dirty
signs: Polly `RetryForever`/`WaitAndRetryForever`, `HttpClient.Timeout =
Timeout.InfiniteTimeSpan`, `CancellationToken.None` passed to an external call
while the entity waits, a `catch` that only logs and leaves the status as is.

**Questions:**
1. Before or during an external call (model, network, queue, background
   handler), does the entity get a waiting state? If there is no external call
   (waiting for a human decision), the answer is "no".
2. Is there a path to a final state (`failed`, `timeout`) for all three: a
   refusal, a timeout, **and** the death of the process between the write of
   the waiting state and the end of the call? A `try`/`except` covers the first
   two only; the death of the process is covered by a lease that another
   worker takes over, a cleaner that reads the waiting state, or a recovery on
   start, in the fragment or explicitly named by it.

**Dirty if:** 1 = yes and 2 = no.

**Does not count:** a call with no waiting state on the entity (the error goes
straight to the caller).

**Dirty:**
```python
version.processing_status = "processing"; db.commit()
text = extract(document)   # the process died: the version stays "processing" forever
```
**Clean:**
```python
enqueue_extraction(version.id)   # a handler with a lease; the cleaner moves overdue work to failed
```

## C12. The screen assembles the state itself

**Search:** in the frontend, a `useState` named `status`, `state`, `phase`,
`stage`, `mode`, `ready`, `pending`, `step`, that is set in `useEffect`, by a
timer (`setTimeout`, `setInterval`), or from `localStorage`; a ladder of three
or more conditions that chooses a screen or a stage.

**Server-rendered pages and plain helpers:** the ladder sits in JSX
(`deal.status ===`, `.every(`, `.some(`) or in an exported `lib/*.ts` function
that takes an API type and returns a boolean or a union (`*needs*`, `*State`,
`*Notice*`); `Date.now()` or `new Date(` compared with a server timestamp
decides an expiry or an overdue state.
The same applies to `.js`/`.jsx` files and to vanilla JS that rebuilds the page
after `fetch(…).then` (`.value =`, `innerHTML =`), and to conditions over the
server object in server templates.

**Kotlin:** Compose: a `remember { mutableStateOf(` named `status`/`phase`/
`ready` that is set in `LaunchedEffect(` or by a `Handler.postDelayed(`, a
`when` ladder of three or more branches over the server object; Android View:
a view model property `Phase`/`IsReady` computed from several DTO fields,
`System.currentTimeMillis() - dto.startedAt >` deciding an expiry.
**Go:** html/template: a ladder of `{{if` over `eq .Status` that picks the
screen, or a FuncMap helper (`expiredSince`, `*Needs*`) that computes a state
for the template; a template that draws by one field of the server object is
the clean case.

**C#:** Blazor: a field `phase`, `status`, `isReady` in `@code` set in
`OnAfterRenderAsync`/`OnParametersSetAsync`, by a `System.Threading.Timer`, or
from `ProtectedLocalStorage`/`ILocalStorageService`; an `@if` ladder over the
server object (`@if (Model.Status == … && Model.Error == null)`). WPF, MAUI,
Avalonia: a view model property `Phase`, `State`, `IsReady` computed from
several DTO fields, an `IMultiValueConverter` that combines them, a
`DispatcherTimer` that declares a failure, `DateTime.UtcNow - dto.StartedAt >`
deciding an expiry. A view model that exposes one server field and a converter
that maps one value to a view are the clean case.

**Questions:**
1. Is the value the state or stage of an entity that is stored on the server
   (a draft, a build, an attempt, an answer, an assignment)?
2. Is it computed in the browser from other fields, flags, a timer, or browser
   storage, rather than taken from one field of the server response? The
   absence of `useState` and `useEffect` changes nothing: a pure function over
   three or more response fields, a ladder of conditions in the markup, and a
   polling loop that declares a failure by the browser clock are all "yes".

**Dirty if:** 1 = yes and 2 = yes.

**Does not count:** state of the interface itself that does not exist on the
server (whether a list is open, which tab, a draft of input, whether a request
is loading); a screen that picks a view by a mapping from one field of the
server response; a timer that only updates the displayed time and does not
declare a failure; tests.

**Dirty:**
```ts
useEffect(() => {
  if (job?.error || Date.now() - startedAt > 90_000) setPhase("failed");
}, [job, startedAt]);
```
**Clean:**
```ts
const phase = draft.stage;   // the server returns the stage, the screen draws by it
```

## C13. The outcome depends on what arrived first

**Search:** in the frontend, the response of an asynchronous request that
writes values into a form or into the user's choice (`prefill`, `seed`,
`apply*`, `onSuccess`, `.then(` with `set*`), while the user can change the
same fields before the response.

**Kotlin:** `lifecycleScope.launch {` that awaits a response and then writes
into two-way bound fields (`binding.field.setText(`, a `mutableStateOf(` the
form reads), with no gate in the fragment (`binding.isEnabled = false`, an
`isLoading` check, `progressBar.isVisible`).
**Go:** no signs — the card's race does not arise in a server-rendered
template: the render happens after the response data is already complete.

**C#:** Blazor: fields bound with `@bind` or an `EditForm` model filled after
`await Http.GetFromJsonAsync` in `OnInitializedAsync`, while the form is already
rendered; WPF, MAUI, Avalonia: an async command or `async void` handler that
writes two-way bound properties after `await`, with no `IsBusy`/`IsEnabled`
gate and no `CanExecute`. Clean: `@if (loaded) { <EditForm …> }`,
`disabled="@isLoading"`, `IsEnabled="{Binding IsIdle}"`.

**Questions:**
1. Does the response of the request write values into fields that the user can
   also change (input, choice, switch)? A value that the screen only shows
   (`readOnly`, a link, a counter) is "no".
2. While the request is running, are these fields available to the user?
3. Is there no rule about who wins (the fields are blocked until the response,
   or the response does not touch what the user changed)?

**Dirty if:** 1, 2 and 3 = yes.

**Does not count:** the response writes only into its own result field
(`readOnly`, a link, a calculation, a counter, display text) and does not touch
the fields the user changes, even if those fields are available during the
request.

**Dirty:**
```tsx
<Wizard prefill={extract.lastResponse} />   // the wizard is available before the parse response
```
**Clean:**
```tsx
{extract.settled ? <Wizard prefill={extract.lastResponse} /> : <Loader />}
```

## C14. A declaration without a writer, or a read with a write

**Search:** the machine collects models, tables and lists and looks for who
creates them and who reads them; separately, `GET` handlers that contain
`commit`, `add`, `update`, `insert`.

**Kotlin and Go (routes):** Spring `@GetMapping`, Ktor `get("/…") {`, Go `r.GET(`, `r.Get(`,
`http.MethodGet`; Go often registers routes in `routes*.go` apart from the
handlers. The write is usually one call away: list the service methods named
`list`, `get`, `count` that contain `update`, `INSERT`, `Exec(`, `.Save(`,
`MarkUsed`, then check their `GET` callers. A constant declared in a domain
package and used nowhere else (a status nobody assigns) is the "declaration
without a writer" half.

**C#:** `[HttpGet]`, `app.MapGet(`, `group.MapGet(`; the write is usually one call
away: services named `Get*Async`, `List*Async`, `Count*Async` that contain
`SaveChangesAsync`, `.Add(`, `.Update(`, `ExecuteUpdateAsync`, Dapper
`ExecuteAsync(`. An `enum` member nobody assigns outside tests, and a `DbSet<T>`
with no `.Add(`/`AddRange(` anywhere, are the "declaration without a writer"
half. `IMemoryCache.Set` and `IDistributedCache` writes are not a database write.

**Questions:**
1. Is there in the list of places outside `tests/` at least one line that
   creates a record of this table or assigns this field (`Name(`,
   `insert(Name`, `.field =`)? An import, `__all__` and `relationship` are not
   a write.
2. Is there outside the declaring module at least one read of this list or
   constant?
3. Does the read handler (`GET`) write to the database?

**Dirty if:** 1 = no, or 2 = no, or 3 = yes. The search puts into the fragment
the declaration and the list of places of use by the name of the thing the
question is about (the field, not only the class).

**Does not count:** writing to an audit log or a view counter, if they are
declared as such; adding a row of a display event with an idempotency key
(`record_*_event`).

**Dirty:**
```python
@router.get("/drafts")
def list_drafts(db):
    for d in drafts: d.structure_json = engine.poll(d.run_id)
    db.commit()
```
**Clean:**
```python
@router.get("/drafts")
def list_drafts(db):
    return [DraftOut.from_orm(d) for d in drafts]   # the structure is written by a background sync
```

## C15. The refusal reaches the user without its code

**Search:** in the frontend, error handlers (`catch`, `onError`, `isError`,
`error &&`, `failed`) that show text to the user without opening the response;
`.catch(() => {})` style handlers that put one text for whatever arrived. On
the server, `HTTPException`/`Problem(` with a string in `detail`, a handler
that writes one text for any failure.
**Kotlin:** a screen that draws one refusal text from an `error != null`
flag. **Go:** `http.Error(w, err.Error()`, `c.JSON(409, gin.H{"error":
err.Error()})`. **C#:** `Problem(ex.Message)`, a page that sets one fixed
error text in the catch.

**Questions:**
1. Does the branch show the user the text of a refusal or hand the refusal to
   the user (a request response, a stored failure field)?
2. Is the refusal code from the server response not read at this place: the
   text is chosen by an error flag or by whatever arrived; or does the refusal
   leave the server as a string with no code from the list, so the client
   cannot tell this reason from any other?

**Dirty if:** 1 = yes and 2 = yes.

**Does not count:** writing to a log; a branch that shows its own text for the
single code chosen by a member of the list and passes the other refusals on by
code; a test.

**Dirty:**
```tsx
onError: () => notify(t("sources.readFailed"))   // the refusal code is not read
```
**Clean:**
```tsx
const text = {
  attachment_pdf_encrypted: "sources.pdfEncrypted",
  attachment_text_char_limit_exceeded: "sources.textTooLong",
} satisfies Record<SourceRefusalCode, string>;
onError: (e) => notify(t(text[e.code]))
```

## C27. One code or one text for several causes

**Search:** a catch of all exceptions that issues a refusal (`except Exception
… raise HTTPException`, `catch (Exception) { return BadRequest("…"); }`), a
`runCatching … getOrElse { <literal> }`, an `@ExceptionHandler` or
`IExceptionHandler` with one code for many causes, a helper that reduces
several codes to one text (`get(code, generic)`, `t("…failure.generic")` as
the only exit), a handler answering `gin.H{"error": "… failed"}` from every
path.
**Go:** one function returning one error text from every failure path.

**Questions:**
1. Does the fragment hand a refusal to the user (a request response, a stored
   failure field, a shown text)?
2. Do several different causes get one code or one text: a catch of all
   exceptions sets a common code, several codes lead to one text, an unknown
   code falls to the same generic text as the known ones?

**Dirty if:** 1 = yes and 2 = yes.

**Does not count:** a catch that only logs and rethrows; each cause mapped to
its own member of the code list with unknown failures rethrown or passed
through as themselves; a test.

## C28. The client declares the refusal codes itself

**Search:** in the frontend, "code → text" tables declared as
`Record<string, …>` or a list of code strings; `` t(`error.${code}`) `` over a
hand-written message catalogue; `switch (code)` over string literals;
`.code === "…"` comparisons deciding the UI, where the code's type is `string`.
**Go:** a `map[string]string` of code texts copied from the contract. **C#:**
a `Dictionary<string, string>` of codes to texts. **Python/Kotlin:** a CLI or
client module keeping the server's codes as its own string constants.

**Questions:**
1. Does the branch show the user text chosen by a refusal code, or map refusal
   codes to texts?
2. Are the codes declared in the client code, as keys of a `Record`, members
   of a string list, cases of a `switch`, or keys of a map — rather than taken
   as a type from the generated contract (`components["schemas"][…]`, a
   generated enum, a shared contracts package)? The server's list is the
   declaration; a client copy diverges silently.

**Dirty if:** 1 = yes and 2 = yes.

**Does not count:** a type imported or generated from the contract; a table
checked against the contract type (`satisfies Record<ContractCode, string>`, a
`when` exhaustive over the generated enum); a test; translating one code the
fragment received as a typed member.

**Dirty:**
```ts
const REFUSAL_TEXT: Record<string, string> = {   // a copy of the contract list
  depot_not_found: "refusal.depotNotFound",
  route_closed: "refusal.routeClosed",
}
```
**Clean:**
```ts
type RefusalCode = components["schemas"]["RefusalCode"];
const REFUSAL_TEXT = {
  depot_not_found: "refusal.depotNotFound",

```

## C16. The writer lets a forbidden transition pass silently

**Search:** the write functions of a state field (`set_*_status`,
`transition_*`, `mark_*`, `apply_*`, methods `setStatus`, `transitionTo`,
`markPaid`): an `if status == X:` that wraps the assignment with no `else`, a
bare `return` / `return False` / `return None` when the old status does not
match, a check written as a list of forbidden statuses (`if status in (PAID,
SHIPPED): raise`) instead of allowed ones. Django: `Model.objects.filter(pk=…,
status=…).update(status=…)` whose returned count is dropped; SQLAlchemy:
`session.execute(update(…).where(… .status == …))` whose `rowcount` nobody reads;
`get_or_none`/`first()` on the old status followed by a bare `return`.

**Kotlin and Go:** `if (status == X) { status = Y }` with no `else`,
`when (status) { X -> …; else -> Unit }`, `if s.Status != X { return nil }`, SQL
`UPDATE … SET status = … WHERE status = …` whose zero affected rows nobody
reads (`RowsAffected` ignored, `execute(` result dropped).
**C#:** `if (Status == X) { Status = Y; }` with no `else`, `_ => { }` in a
switch over the old status, `return false` from `TryMark*` that the caller
ignores, `ExecuteUpdateAsync` with the old status in `Where` and the returned
row count ignored.

**Questions:**
1. Is the fragment the write function of a state field (it assigns the field
   or issues the `UPDATE` that changes it)?
2. Is there a path where the old status is not one the transition allows, the
   new status differs from the old one, and the function returns without a
   refusal (no exception, no refusal code, no recorded conflict state) and
   without making the caller check a result? An old status the branch does not
   name is not allowed; the full list of statuses is not needed to answer. A
   result the caller in the fragment ignores counts as not checked.
3. Are the allowed old statuses written inside this function, branch by branch,
   rather than read from one transition table?

**Dirty if:** 1 = yes and 2 = yes. Question 3 = yes makes the place worse: the
next writer will copy the branch with other statuses.

**Does not count:** a repeat of the same target status (`if status == new:
return`): that is idempotency, not a transition; a function that on a
mismatch moves the entity to a declared conflict state or raises; an `UPDATE …
WHERE status = …` whose affected row count is checked and turned into a
refusal; a function that does not assign the field itself but hands the
transition to the one writer (`set_*_status(…)`, `transition(…)`), which checks
the table; a skip of an event that the function's docstring or a comment names
as stale, duplicate or outranked by a newer answer (an ordering rule, card C13);
tests.

**Dirty:**
```python
def mark_paid(order):
    if order.status == OrderStatus.STOCK_CONFIRMED:
        order.status = OrderStatus.PAID
    # cancelled, shipped: returns as if paid
```
**Clean:**
```python
def mark_paid(order):
    if order.status == OrderStatus.PAID:
        return                                  # a repeated message
    transition(order, OrderStatus.PAID)         # raises on a pair outside the table
```

## C17. The client decides what the user is allowed to do

**Search:** in the frontend, a comparison of a status, a date, or a counter from
a server response next to whether an action is offered: `canCancel`, `canEdit`,
`canRetry`, `isEditable`, `showRetry`, `disabled={…status…}`, a button rendered
under `status === "…"`, `Date.now() < deadline`, `attempts < MAX_ATTEMPTS`,
`role === "admin"` choosing a button.

**Server templates (Jinja, Django, ERB, Razor):** `{% if order.status == "…" %}`
or `{% if obj.attempts < 3 %}` around a `<button>`, a form or a link to an
action: a template is a client like the browser; a Python helper `can_*` used
only by templates while the view repeats the condition.

**C# clients (Blazor, WPF, MAUI, Avalonia):** `IsVisible`, `IsEnabled`,
`CanExecute`, `disabled="@(…)"` computed from `Status ==` or
`.Equals("…")`, a deadline or an attempt counter; a view model property
`Can*` or `Is*Order` built from the order's status.

**Questions:**
1. Does the branch decide whether the user may perform an action (a button is
   shown or enabled, a command can run, a form can be submitted, a route
   opens)? Choosing only how something looks (a color, a label, an icon) is
   "no". A property or variable whose name answers this question
   (`isCancellable`, `canEdit`, `showRetry`) counts as "yes" even when the
   markup that binds it is not in the fragment.
2. Is the decision computed on the client from a status, a date, a counter, or
   a role, rather than read from a field of the server response that answers
   this question (`can_cancel`, `allowed_actions`, an action link)?

**Dirty if:** 1 = yes and 2 = yes.

**Does not count:** a check of the shape of input (a required field, a length,
an email format); a template that calls the same function the action's view
calls to refuse (`{% if order|can_cancel %}` with `can_cancel` used by the
view); hiding an action while its own request is in flight; a
branch that reads a server field which answers the question, even if it also
reads other fields for display; tests.

**Dirty:**
```ts
const canCancel = order.status === "submitted";
{canCancel && <Button onClick={cancel}>Cancel</Button>}
```
**Clean:**
```ts
{order.allowedActions.includes("cancel") && <Button onClick={cancel}>Cancel</Button>}
```

## C18. Direct I/O inside a rule or a request handler

**Search:** `sqlite3`, `smtplib`, `imaplib`, `urllib`, `requests`, `httpx`; driver
calls `connect(`, `execute(`, `executemany(`, `executescript(`, `urlopen(`,
`SMTP(`, `sendmail(`, `IMAP4(`; SQL inside strings — `SELECT`, `INSERT INTO`,
`UPDATE`, `DELETE FROM`, `CREATE TABLE`, `PRAGMA`, `WITH` — including multiline
strings, aliases and SQL handed to a driver.
**Kotlin:** `DriverManager.getConnection(`, `connection.prepareStatement(`,
`jdbcTemplate.query(`, `jakarta.mail`/`javax.mail` `Transport.send(`, a bare
`HttpClient`/`OkHttpClient` call inside a service or a controller method.
**Go:** `sql.Open(`, `db.Exec(`, `db.Query(`, `db.QueryRow(`, `http.Get(`,
`http.Post(`, `smtp.SendMail(` inside a function that also picks a state or
serves a request.
**C#:** `new SqlCommand(`, Dapper `connection.Execute(` / `connection.Query(`,
EF Core `ExecuteSqlRaw(` / `ExecuteSqlInterpolated(`, `new HttpClient(`,
`httpClient.GetAsync(` / `.PostAsync(`, `new SmtpClient(`, MailKit `ImapClient`,
SQL in strings handed to a driver — inside a controller action, a minimal API
endpoint or a service method that also decides a state, enforces a rule in a
`WHERE` or computes a value shown to the user.

**Questions:**
1. Does this function itself call a database, mail or HTTP driver? A call of the
   project's own adapter method (`store.save(…)`, `mailbox.read(…)`) is "no": the
   driver is not here.
2. Does the same function do something that is not transport: choose or return a
   state or a refusal (instead of raising the driver error), enforce a rule of the
   domain (a guard in a `WHERE`, a uniqueness rule in a `CREATE INDEX`), compute a
   value shown to the user, or serve a request (a route handler, a CLI command)?
   Returning `NOT_PREPARED` on a driver error is choosing a state.

**Dirty if:** 1 = yes and 2 = yes.

**Does not count:** an adapter function whose whole job is the driver (a storage,
mail or HTTP adapter) and which only maps the driver's error to a code; a
function that calls an adapter method and then decides — the driver stays behind
the method; schema creation or connection set-up with no domain rule in it; tests.
Judge each function on its own: a class being a storage adapter does not excuse a
method whose `WHERE`, index or error branch carries a rule or a state of the
entity — that method is dirty.

**Dirty:**
```python
def append_message(run_id: int, message: str) -> None:
    # only a run that is still going may take another letter — the rule is in the WHERE
    db.execute("UPDATE runs SET later = json_insert(later, '$[#]', ?) "

```
**Clean:**
```python
def append_message(runs: Runs, run: Run, message: str) -> Run:
    if run.state is not RunState.RUNNING:
        raise Refused.NOT_RUNNING
    runs.append(run, message)      # the adapter owns the driver
```

**C#:** `using Microsoft.AspNetCore.` in a service, repository or domain file —

## C20. Raw keys of a config or an external payload

**Go:** `viper.Get("…")` outside the one config load, `json.Unmarshal` into

**Questions:**
1. Did the value come from outside the code — a config file, a network or
   product payload, a mail, a stored JSON that an earlier version wrote — and is
   that mapping still a raw dict at this point?
2. Is the key read by a literal where the mapping is not turned into a typed
   value: no dataclass, enum or TypedDict is built in the fragment, and the
   fragment is not the one decoder of that payload?

**Dirty if:** 1 = yes and 2 = yes.

**Does not count:** the single decoder that takes the parsed payload and returns
typed objects — its key reads are the schema; building an outgoing payload — the
literal is a key of the dict this fragment writes (a dict literal or an
assignment target), not a read of a mapping that came from outside: reading the
config or the payload that feeds the payload is still dirty; a mapping built and
read in the same fragment; columns of a database row read by the storage adapter
next to the SQL that produced them; scalar environment variables read into
typed parameters, even several of them; tests.

**Dirty:**
```python
DOCUMENTS = settings["documents"]


def title(kind: str) -> str:
    return DOCUMENTS[kind]["print"]["title"]
```
**Clean:**
```python
@dataclass(frozen=True)
class Document:
    name: str
    title: str


@dataclass(frozen=True)
class Settings:
    documents: Mapping[str, Document]


def load_settings(raw: dict) -> Settings:      # the one decoder of the config file
    return Settings(documents={name: Document(name=body["name"], title=body["print"]["title"])
                               for name, body in raw["documents"].items()})
```

## C21. State derived from another field of the same entity

**Search:** functions that return or write a lifecycle state — names like
`*_state`, `*_status`, `resolve_*`, `compute_*`, `classify_*`, `derive_*` — and
branches in which a state literal is chosen from a non-state field of the same
object. The non-state field is usually an artifact or an outcome: `audio_path`,
`audio_url`, `file_path`, `result_url`, `output_path`, `download_url`,
`completed_at`, `generated_at`, `finished_at`, `result`, `output`, `error`,
`duration`. Signs: `if …path…: return "ready"`, `or payload.get("audio_path")`,
`?? "ready"`, `payload.AudioPath is not null ? "ready"`. Look at tests that
pass a stored `state` together with such a field and expect the state implied
by the artifact.
**Kotlin:** `payload.audioPath != null`, `completedAt != null`,
`resultUrl.isNotBlank()`, `?: GenerationState.READY` or a `when` branch that
returns a lifecycle state from one of these fields.
**Go:** `if p.AudioPath != "" { return "ready" }`, `p.CompletedAt != nil`,
`len(p.Output) > 0`, `p.Error != ""` in a function returning a state or status.
**C#:** `payload.AudioPath is not null`, `payload.CompletedAt.HasValue`,
`!string.IsNullOrEmpty(payload.ResultUrl)`, a ternary or `switch` arm that
returns `Ready`/`Completed`/`Failed` from one of these fields.

**Questions:**
1. Does the fragment return or write a lifecycle state of an entity, or assert
   the exact state returned by such a function?
2. Is the choice of that state influenced by another field of the same entity
   that is not its lifecycle state: an artifact path or URL, a result, output,
   error, duration, or a completion timestamp? In a test, an input-output pair
   in which the stored state says one thing and the artifact makes the result
   another is "yes".
3. Is a stored `state`/`status` of the entity visible in the fragment, while
   the other field ignores it or has higher priority?

**Dirty if:** 1 = yes and 2 = yes and 3 = yes.

**Does not count:** a separate artifact-availability field (`playable_audio_path`,
`download_url`) returned next to the lifecycle state; a migration or backfill
that fills the stored state once; a report or metric that does not return the
entity's lifecycle state; a writer that stores the new state and the artifact
as data of the same transition. Tests that only mirror a pass-through of the
stored state are not separate places; a test whose input-output pair requires
an artifact to outrank the stored state is a dirty expectation and a signal to
find the production derivation.

**Dirty:**
```python
def engine_payload_state(payload):
    state = payload["state"]
    if state in {"failed", "resource_limit_exceeded"}:
        return "failed"
    if state == "ready" or payload.get("audio_path"):
        return "ready"
    return "generating"
```
**Clean:**
```python
def engine_payload_state(payload):
    return payload["state"]


def payload_view(row):
    return {
        "state": row.state,
        "playable_audio_url": row.audio_url,
    }
```

## C22. An external call without a deadline

**Search:** `requests.get(`/`post(`/`put(`/`patch(`/`delete(`/`request(`,
`httpx.get(`/`post(`/`stream(`, `urllib.request.urlopen(`, `socket.create_connection(`,
`subprocess.run(`, `subprocess.call(`, `subprocess.check_output(`, `Popen(`.
**TS:** `fetch(`, `axios.get(`/`post(`/`put(`/`delete(`, `http.request(`.
**Go:** `http.Get(`, `http.Post(`, `http.DefaultClient`, `client.Do(`, `exec.Command(`.
**Kotlin:** `OkHttpClient()`, `.newCall(`, `URL(`.`openConnection(`, `ProcessBuilder(`.
**C#:** `new HttpClient(`, `.GetAsync(`, `.PostAsync(`, `.SendAsync(`, `Process.Start(`.

**Questions:**
1. Does the fragment itself call out: an HTTP request to another system, an
   open socket, or a child process? A call of the project's own adapter method
   (`api.fetch(…)`, `mail.send(…)`) is "no": the deadline lives with the adapter,
   in a fragment of its own.
2. Is there no deadline declared in the fragment: no `timeout=` on the call and
   none on the client or session the call is built from, no `AbortSignal`/
   `AbortSignal.timeout(`, no `CancellationToken`/`ct:` passed, no
   `context.WithTimeout(`, no `client.Timeout`, no `.callTimeout(`/`.requestTimeout(`?

   deadline, even when the library would apply an implicit one: the declaration
   must be in the code, not in the library's default.

**Dirty if:** 1 = yes and 2 = yes.

a subprocess call with `timeout=`; tests.

**Dirty:**

    return Decimal(r.json()["rate"])

```python
def fetch_rate(session: Session, pair: str) -> Decimal:

## C23. A side effect hidden in a constructor, a getter, or an ORM hook

**Search:** `@event.listens_for`, `after_insert(`, `before_insert(`,

Django `@receiver(`, `post_save(`, `pre_save(`, `post_delete(`; `@property`

## C24. A background task whose failure is lost

**Search:** `asyncio.create_task(`, `loop.create_task(`, `threading.Thread(`,
`.start()` on a thread; a call of an async function with `void ` or no `await`
and no `.then(` in the fragment. **TS:** `void someAsync()`, a promise dropped
without `.catch(`. **Go:** `go func(`, `go ` statement. **C#:** `Task.Run(`,
`Task.Factory.StartNew(`, `_ = ` before an async call. **Kotlin:**
`GlobalScope.launch(`, `scope.launch(` with no handler, `thread(start = true)`.

**Questions:**
1. Is a background job started and its completion neither awaited, joined nor
   checked anywhere in the fragment (fire and forget)?
2. Would its failure be lost: no done-callback that records the error, no error

   later — and in Python no strong reference to the task either, so it can be
   garbage-collected mid-flight?

**Dirty if:** 1 = yes and 2 = yes.

**Does not count:** the job body itself catches and records failures (a

```
**Clean:**
```python
def on_payment(payment, tasks: TaskSet):

    tasks.add(t)                        # the registry holds it

```

## C25. The clock or the random generator called inside a rule

**Search:** `datetime.now(`, `datetime.utcnow(`, `time.time(`, `uuid.uuid4(`,
`random.`; **TS:** `Date.now(`, `new Date(`, `Math.random(`. **Go:** `time.Now(`,
